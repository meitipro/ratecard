## How validators agree

The leader asks its model and returns one string, the label: XS, S, M, L, XL or NONE. Each validator asks its own model the same prompt and agrees only when its own label is exactly the leader's. Nothing else is compared and nothing else is stored from the model, so agreeing on the label is agreeing on the pay.

The price is then looked up on the card by the label, and the cap is applied, in contract code. The model never sees a price. Between two tiers the prompt picks the smaller, a deliberate tie break so a pool is never overspent by a generous reading; the appeal exists for the cases where that is unfair.

An answer that cannot be read (not JSON, or a label outside the six) is retried once, then fails the round. It never becomes a label.
